# IVF development tests

## Current review segment: S01 — input contracts and PQ reuse

Implemented:

* `BuildConfig` / `SearchConfig` validation and bounded rerank candidate counts.
* Packed vector, PQ code, GT-header, counted-ID, and five-offset PQ-pivot validation.
* `PQCodebook<T>` wraps the existing `FixedChunkPQTable<T>` encoder and ADC LUT.
* Optional ADC-only PQ loading, without PQ-to-PQ tables or runtime cache writes.
* Strict `ivf_build` / `ivf_driver` **validation-only** command scaffolds.

The tools require `--validate_inputs 1`. They do not build/search an index,
write heaps, apply updates, or emit benchmark results. `nlist` is explicit in
the driver until manifest loading is implemented. Metadata validation checks
vector payload length, not every vector's coordinate values; finite-coordinate
validation belongs to the later streaming loader/trainer.

PQ pivots must use the five-offset format generated by the current helpers.
The older multi-sidecar format is rejected explicitly. Dimensions and chunk
counts are read from validated pivots, not inferred from a default.

### Prerequisite fix: S00 — logger overflow

ASan found an existing write past the logger's one-byte put buffer during PQ
loading. `src/logger.cpp` now flushes a full buffer before appending. The CLI
test checks exact output for a 4097-character message plus its suffix. This
small prerequisite can be reviewed independently of the IVF changes.

## Run (Linux / Ubuntu WSL)

From `ivf-only/`:

```bash
cmake -S tests/ivf -B build/ivf-contracts -DCMAKE_BUILD_TYPE=Debug
cmake --build build/ivf-contracts -j4
ctest --test-dir build/ivf-contracts --output-on-failure
```

This isolated build requires a C++20 compiler, CMake >= 3.16, and Python 3.
It reuses the real PQ header/logger, but needs no MKL, libaio, or dataset.
Fixtures are written only into this build tree. The normal BufANN build also
provides the command targets; tests there are opt-in with
`-DIVF_BUILD_CONTRACT_TESTS=ON` and require its existing build dependencies.

Address/undefined sanitizers:

```bash
cmake -S tests/ivf -B build/ivf-contracts-sanitized \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer"
cmake --build build/ivf-contracts-sanitized -j4
ctest --test-dir build/ivf-contracts-sanitized --output-on-failure
```

Fast-math regression check:

```bash
cmake -S tests/ivf -B build/ivf-contracts-fast \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS=-Ofast
cmake --build build/ivf-contracts-fast -j4
ctest --test-dir build/ivf-contracts-fast --output-on-failure
```

Validation targets explicitly disable fast-math so NaN/Inf checks survive the
parent project's optimization flags. Contract tests use checked failures, not
C++ `assert`, so they still test in Release.

## Coverage and limits

`ivf_contracts` covers invalid counts/settings, sample support, candidate ceiling
and clipping, dtype/dimension mismatches, truncated/trailing binary data, GT
shape, duplicate/out-of-range IDs, corrupt PQ offsets/permutations/chunks,
non-finite pivots/means, and explicit rejection of the legacy pivot format.

PQ tests cover float/int8/uint8, signed and high uint8 coordinates, nonzero
global centering, a nonidentity dimension permutation, unequal chunk lengths,
encoder/LUT parity with the existing loader, a reconstruction oracle, retained
legacy PQ-to-PQ behavior, and eight concurrent readers with separate scratch.
They test synthetic pivots, not a trained SIFT index or the standalone PQ
builder's assignment implementation; those integration checks remain pending.

`ivf_cli_contracts` covers all supported dtypes/workload names, JSON validation
records (without fake metrics), invalid flags/numbers, missing mutation inputs,
help, refusal to execute an unimplemented workload, and logger output.
