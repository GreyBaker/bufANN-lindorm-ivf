# IVF development tests

## S01 — input contracts and PQ reuse (retained)

Implemented:

* `BuildConfig` / `SearchConfig` validation and bounded rerank candidate counts.
* Packed vector, PQ code, GT-header, counted-ID, and five-offset PQ-pivot validation.
* `PQCodebook<T>` wraps the existing `FixedChunkPQTable<T>` encoder and ADC LUT.
* Optional ADC-only PQ loading, without PQ-to-PQ tables or runtime cache writes.
* Strict `ivf_build` / `ivf_driver` input-validation modes (retained).

Dependency-isolated `ivf_build`/`ivf_driver` require `--validate_inputs 1`; they do not build/search
an index or emit benchmark results. Full Linux routing-enabled tools now provide
native build/search execution (see S04 below). In validation mode, `nlist` is
explicit and source PQ metadata is checked. Metadata validation checks
vector payload length, not every vector's coordinate values; finite-coordinate
validation is implemented by the separate S02 loader/S03 trainer components.

PQ pivots must use the five-offset format generated by the current helpers.
The older multi-sidecar format is rejected explicitly. Dimensions and chunk
counts are read from validated pivots, not inferred from a default.

### Prerequisite fix: S00 — logger overflow

ASan found an existing write past the logger's one-byte put buffer during PQ
loading. `src/logger.cpp` now flushes a full buffer before appending. The CLI
test checks exact output for a 4097-character message plus its suffix. This
small prerequisite can be reviewed independently of the IVF changes.

## Run (Linux / Ubuntu WSL)

From `ivf-only/`:

```bash
cmake -S tests/ivf -B build/ivf-contracts -DCMAKE_BUILD_TYPE=Debug
cmake --build build/ivf-contracts -j4
ctest --test-dir build/ivf-contracts --output-on-failure
```

This isolated build requires a C++20 compiler, CMake >= 3.16, and Python 3.
It reuses the real PQ header/logger, but needs no MKL, libaio, or dataset.
Fixtures are written only into this build tree. The normal BufANN build also
provides the command targets; tests there are opt-in with
`-DIVF_BUILD_CONTRACT_TESTS=ON` and require its existing build dependencies.

Address/undefined sanitizers:

```bash
cmake -S tests/ivf -B build/ivf-contracts-sanitized \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer"
cmake --build build/ivf-contracts-sanitized -j4
ctest --test-dir build/ivf-contracts-sanitized --output-on-failure
```

Fast-math regression check:

```bash
cmake -S tests/ivf -B build/ivf-contracts-fast \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS=-Ofast
cmake --build build/ivf-contracts-fast -j4
ctest --test-dir build/ivf-contracts-fast --output-on-failure
```

Validation targets explicitly disable fast-math so NaN/Inf checks survive the
parent project's optimization flags. Contract tests use checked failures, not
C++ `assert`, so they still test in Release.

## S02 prerequisite — graph-free heap

`ivf_heap_tests` is available only in the full Linux BufANN configuration with
`IVF_BUILD_CONTRACT_TESTS=ON`. It tests zero-degree, no-PQ storage for all dtypes;
guarded padded-coordinate copies into aligned scratch; external tags;
publication; flush and clean reopen. An unpublished allocation stays invisible,
but its checkpoint is explicitly rejected by the backend. Streaming loading,
the IVF storage adapter, allocation rollback, and batched candidate fetches
are not implemented by this prerequisite test.

## S02 adapter and streaming loader

`ivf_heap_adapter_tests` exercises `HeapStorage<T>` with all dtypes, full-file
and base-prefix loading, stable/sparse IDs, padded aligned reads, immutable
checkpoints and concurrent read-only reopen. Invalid append arguments have no
effect. Failed streams/backend mutations poison checkpointing rather than
claiming allocation rollback. Existing files are not overwritten.
See [s02-heap-adapter.md](../../docs/s02-heap-adapter.md) for the API, failure,
snapshot and concurrency limits. The adapter suite passes Debug ASan/UBSan with
leak detection (1/1); the S02 Release configuration passed 4/4 suites. S02 is
implemented/tested at this review boundary; complete IVF execution is still pending.

## S03 — exact/HNSW training and pinned hnswlib routing

The default isolated build now adds `ivf_centroid_training` without downloading
dependencies (3 suites total). Add `-DIVF_BUILD_ROUTING=ON` to enable the
checksum-pinned, unmodified hnswlib v0.8.0 router and `ivf_centroid_routing`
(now 7 Linux routing-enabled isolated suites; 13 in the full configuration, 14 with optional trained helpers).

```bash
cmake -S tests/ivf -B build/ivf-s03-release \
  -DCMAKE_BUILD_TYPE=Release -DIVF_BUILD_ROUTING=ON
cmake --build build/ivf-s03-release -j4
ctest --test-dir build/ivf-s03-release --output-on-failure
```

The exact and HNSW-assisted trainers and immutable centroid router are tested
components, not a complete IVF build. Production-scale quality/budgets remain
pending. Router builds always use upstream's `NO_MANUAL_VECTORIZATION` to avoid
an ASan-confirmed upstream SSE-prefetch out-of-bounds read. No upstream source
is patched and no sanitizer check is suppressed. hnswlib is Apache-2.0 licensed.

At the S03 boundary, full-project Release passed 6/6 and isolated ASan/UBSan
with leak detection passed 4/4. Default routing-disabled isolation passes 3/3.
Details, artifact format, recall
fixture, concurrency and reproduction commands are in
[s03-centroid-training-routing.md](../../docs/s03-centroid-training-routing.md).

`ivf_centroid_scale_smoke` is an explicitly invoked resource test, not routine
CTest or an IVF benchmark. Its synthetic 100K-row/13D, 50K-centroid training and
router persistence/reopen pass. Resource allowances, measured time/RSS and limits
are recorded in the S03 document. It makes no production recall/QPS claim.

## S04 — immutable lists and query composition (partial)

`ivf_posting_lists` tests streamed base-only centroid assignment, unchanged PQ
code repacking, one membership per stable ID, bounded ADC against a direct-code
oracle, ties/empty lists, workspace/work refusals and concurrent scans. It is
available in isolated routing-enabled builds without BufANN/MKL/libaio.

Full-project `ivf_query_composition` uses the real heap/backend with the existing
PQ adapter: routing, LUT construction, list scanning and **actual libaio batch
pinning** followed by aligned copies and exact L2 reranking. All-list/full-budget
queries match a direct-vector oracle for all dtypes; limited-probe results match
an independent ADC/rerank oracle. Batch capacity respects the smallest pool
shard, with conservative serialized adapter pin/copy admission. Tests cover heap
reopen, duplicates, tiny pools, missing IDs, empty/short results, concurrent
queries and measured cold/resident heap-page reads (not device IOPS).

Current full-project Release with trained helpers enabled: **14/14 pass**; Linux isolated routing-enabled Release and
ASan/UBSan with leak detection: **7/7 each**. Full instrumented-backend query and
adapter suites each pass **1/1** with leak detection. The original BufANN driver
still builds. Details and commands:
[s04-lists-query-components.md](../../docs/s04-lists-query-components.md).

List persistence and manifest-bound native build/open/query bundles now pass
fixture tests, including relocated reopen without original inputs and rehashed
structural mismatches. Details:
[s04-index-bundles.md](../../docs/s04-index-bundles.md).
Full Linux routing-enabled tools now support native builds and `search_only`
execution with `--validate_inputs 0` (or omitted); isolated tools still refuse
execution. Validation-only records remain metric-free, and mutations remain
refused in execution mode. `ivf_cli_execution` verifies exact results, SPFresh
interleaved result files and unchanged tie-aware GT scorer parity for all dtypes,
concurrency, short results, collisions and invalid input/budget paths. Full
instrumented CLI and query suites each pass 1/1 with ASan/UBSan and leak detection.
Usage, truthful timing/read/RSS scopes and limits:
[s04-cli-execution.md](../../docs/s04-cli-execution.md).
Query prepare/run scripts and fixture trained-helper parity now pass;
see [benchmark/IVF/README.md](../../benchmark/IVF/README.md) and

The trained helper test is opt-in through `IVF_PQ_PIVOT_HELPER` and

## S05 — mutable lists, sessions, checkpoint and mutation execution (implemented)

`MutablePostingLists` now implements contiguous ID/code arrays with exact +16
growth, stable preallocated ID locators, move-only prepublication reservations,
swap-with-last deletion and per-list shared/exclusive locks. It provides copied
locations/list snapshots and bounded ADC scans, not borrowed mutable pointers.
Successful deleted IDs are not reused; missing deletion is counted/idempotent.
Growth accounts for concurrent old/new allocations and failures permit retry.
Immutable CSR conversion preserves base membership and supplied PQ code bytes.

`ivf_mutable_posting_lists` passes in isolated/full Release and ASan/UBSan with
leak detection. Its contention fixtures also pass **30/30** TSan repetitions with
per-process ASLR disabled; default TSan startup is incompatible with this WSL
memory layout. No suppressions or global kernel changes were used.
The component alone is not native heap/checkpoint integration or S06's 8+8 workload.
Detailed list contracts/reproduction:
[MUTABLE_LISTS.md](../../docs/MUTABLE_LISTS.md).

The separate `MutableIndex<T>` API now forks an immutable bundle onto a verified
private heap, composes frozen routing/existing PQ encoding with prepared-heap/list
publication, supports logical deletes without committed-ID/slot reuse, and
revalidates live candidates during mutable reranking. Native all-dtype fixtures,
including backend growth failure, retries and concurrent mutations/queries, pass
Release and ASan/UBSan. Separate mutable checkpoint/reopen now preserves arbitrary
live sets, tombstones, aborted heap slots, list capacities/order and counters,
with lifecycle quiescence, relocated/new-generation fixtures and rehashed
structural corruption refusal. Fork/reopen exclusively create a private heap
and its `.pq.bin` sidecar; saved families are immutable. Native `insert_only`,
`delete_only` and sequential `search_after_update` now execute; scripts use shared
canonical split/ID/GT helpers and post-update checkpoint reopen/scoring. CLI and
shell pair oracles cover all dtypes, signed/high-byte data, no-reuse/idempotent
deletes, source identity/error/collision refusal, count overrides that preserve
base membership, insufficient GT survivors and source/base/cache preservation.
Update-loop and final-query records remain separate; no concurrent mixed mode is
implied. Native TSan qualification requires a narrowed single-OpenMP-worker run;
the parallel legacy loader configuration is not qualified. Session ownership,
budgets, verification commands and limitations:
[MUTABLE_INDEX.md](../../docs/MUTABLE_INDEX.md).
CLI/script contracts: [s05-cli-and-mutation-harness.md](../../docs/s05-cli-and-mutation-harness.md).

Final S05 revision: full Release **14/14** (optional trained helpers enabled);
selected full ASan/UBSan **6/6** (mutable lists/session, immutable query, heap
adapter, CLI and query/mutation harness) with leak detection. Isolated
routing-enabled Release/ASan+UBSan **7/7 each**, routing-disabled **3/3**.
Native TSan repeats **10/10** and all-dtype mutation CLI TSan **1/1**, with
process-only ASLR disable and `OMP_THREAD_LIMIT=1`; no unrestricted legacy parallel
OpenMP or system-library qualification is claimed. The original `bufann_driver`
still builds. These are functional fixtures, not production benchmark evidence.

## S06 — concurrent mixed rounds

`ivf_mixed_scheduler` tests weighted dense dispatch, uneven stream exhaustion,
joined callback failures and deterministic simultaneous 8+8 callback admission.
Startup-gate regressions check release/abort before and racing with eight waiters;
the wait predicate is mutex-protected even when later worker creation fails.
It also runs in dependency-isolated builds; isolated TSan passes **30/30**
repetitions with process-only ASLR disable, no OpenMP limit or suppressions.
The shared weighted pool's only change is joining already-created workers on
thread launch failure; ordinary dispatch semantics are preserved.

Native all-dtype session fixtures now run three weighted/fixed rounds with
same-centroid insert growth/swap deletion, concurrent rerank coordinate checks,
quiescent list/membership/exact-oracle validation and checkpoint/reopen after each
round. Dedicated-role fixture gates prove eight mutation/eight query callbacks
are simultaneously admitted; production code uses no such fixture barrier.
`ivf_mixed_execution` runs real two-round shell/CLI fixtures for all dtypes,
canonical range/GT helper parity, independent SPFresh scoring, checkpoint chaining,
source/base preservation and invalid count/budget/allocation/input/output refusals.
It now also induces a fixture-local shared-extractor mismatch after a valid native
round and requires retained round/checkpoint evidence but no next round or final
summary. Canonical extraction/byte checks happen inside round orchestration before
subsequent admission/final publication, not in a shell loop after a success summary.

Concurrent queries are weakly consistent and never scored against final GT.
Post-round recall is measured after all foreground workers join and checkpoint
validation completes. Weighted role counts share one pool; fixed mode is truly
eight mutation/eight query workers, not a graph-maintenance allocation.
See [s06-mixed-workloads.md](../../docs/s06-mixed-workloads.md) for commands,
memory/timing/overlap scopes and final verification records.

## Coverage and limits

`ivf_contracts` covers invalid counts/settings, sample support, candidate ceiling
and clipping, dtype/dimension mismatches, truncated/trailing binary data, GT
shape, duplicate/out-of-range IDs, corrupt PQ offsets/permutations/chunks,
non-finite pivots/means, and explicit rejection of the legacy pivot format.

PQ tests cover float/int8/uint8, signed and high uint8 coordinates, nonzero
global centering, a nonidentity dimension permutation, unequal chunk lengths,
encoder/LUT parity with the existing loader, a reconstruction oracle, retained
legacy PQ-to-PQ behavior, and eight concurrent readers with separate scratch.
Those contract tests use synthetic pivots. The separate optional
`ivf_trained_helper_integration` now tests the actual standalone trainer/assignment
against native encoder/ADC and exact script results for every dtype on small
4096-row/13D fixtures; no trained production SIFT index is qualified.

`ivf_cli_contracts` covers all supported dtypes/workload names, JSON validation
records (without fake metrics), invalid flags/numbers, missing mutation inputs,
help, refusal of execution-only flags in validation mode/isolated execution,
invalid or incomplete native requests, and logger output.
